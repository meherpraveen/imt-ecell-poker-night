# E-Cell Poké Poker Night

The event homepage, player registration and live floor run on GitHub Pages. To register, enter a nine-digit roll number or the email already on the student record. The club emails a six-digit sign-in code to that registered address. Returning players can sign in on another device to recover their registration. Anyone can view the live floor. The directory, payment screenshots and staff invitations stay in the club’s private Google files.

## Club desk

1. Import the private workbook into Google Sheets. The **Students** tab uses the columns **Roll Number**, **Name**, **Mail ID** and **Number**. Preserve roll numbers and phone numbers as text.
2. Run `npm install` and `npm run build`. Deploy the contents of `.deploy/` to the club’s Apps Script project. For an existing private Sheet and screenshot folder, add a deployment-only server file containing `const CLUB_RESOURCES = {book: 'SPREADSHEET_ID', folder: 'DRIVE_FOLDER_ID', owner: 'CLUB_EMAIL'};`. Omit that file to let setup create a new private Sheet and folder, then import the directory into its Students tab.
3. When the project is attached to the private Sheet, reload the Sheet as the club owner and choose **Poké Poker Night → Set up club desk**. You can also select **setupEvent** and **Run** in the Apps Script editor. Authorize Sheets, Drive and event email delivery. Deploy as a **Web app**, executing as the owner, accessible to **Anyone**. Set the published HTTPS `/exec` URL in `web/config.js` and rebuild. GitHub Pages publishes the `docs/` folder.
4. On the event sign-in page, the owner enters the configured club email and verifies the **Poké Poker Night 2026 admin sign-in code** from that inbox. The site opens the private desk. The owner can also use **Staff → Private desk link** in the club Sheet and request a code on that page. In **Settings → Registration and payments → Add receiver**, enter the receiver’s name and UPI ID, upload the matching QR and activate it. The club stores it in private Drive. Disabling an account stops new payments to it. Changing its UPI ID archives the old account so its original statements remain identifiable.
5. Under **Settings → Volunteer access**, the owner can issue a desk, gate or floor invitation. Give each volunteer their own link and key privately. Set **Active** to **no** in their Staff row to revoke access.

## Email sign-in

Codes last 10 minutes and work once. A student can request another after one minute. Five incorrect entries lock that code, and the service sends at most five codes per account in 24 hours. A resend keeps the same active code and its remaining guess limit. The screen reports mail failures and send limits. If the message is missing, open **Email hasn’t arrived?** and enter the roll and registered address together to check the match and request delivery. Both roll and email sign-in require one unique address in the directory. E-Cell can resolve a missing or shared address after checking the student’s college ID.

A verified student stays signed in on the same browser for 30 days, including after closing it. The server checks the session and directory on return. A student who leaves to read their sign-in email returns to the same code screen. An expired code can be replaced there. **Sign out** revokes the session and clears that student’s device drafts. The private desk session lasts eight hours.

If Outlook files a requested code in Junk Email, the student can use **Open Outlook Junk Email** on the code screen and enter that code before it expires. A student moving a message changes their own mailbox. Google accepting a send does not report the destination folder.

When several students report Junk placement, the coordinator can give IMT IT the subject **Poké Poker Night 2026 sign-in code**, the club’s sending address and the approximate arrival time in IST. Send one affected recipient’s address privately to IT with their permission. An Exchange administrator can trace the original message, inspect its authentication results and filtering verdict, and submit a verified false positive in Microsoft Defender under **Submissions → Emails → Should not have been blocked**. [Exchange message trace](https://learn.microsoft.com/en-us/exchange/monitoring/trace-an-email-message/trace-an-email-message) · [Microsoft Defender submissions](https://learn.microsoft.com/en-us/defender-office-365/submissions-admin)

The club’s personal Gmail account has an Apps Script quota of 100 email recipients per 24-hour quota period, shared by login codes, resends and pass emails. The app reserves the last available email for the owner. Students who have signed in can also see their approved entry code in their receipt. If the limit is reached on event night, staff can use the existing college-ID and payment-verification flow at the venue. [Google Apps Script quotas](https://developers.google.com/apps-script/guides/services/quotas)

## Payments and entry

Registration opens on 23 November. The currency, entry prices, retry fee and Early Bird cutoff live in [gas/Pricing.gs](gas/Pricing.gs). Change `ENTRY_PRICING.earlyBirdEndsAt` to move the deadline, including its time-zone offset, then rebuild both packages. Registration and checkout display the time remaining and the standard price beside the offer.

Students can return to the same registration to pay while entry is available. Unpaid checkouts do not reserve places. Submitting proof allocates the next available qualifier wave under the event lock. If all waves fill while a student pays, their proof is saved for the desk. The server records which receivers were offered, the student's choice and the fee for the transfer time. A verified Early Bird transfer can be reconciled after the cutoff. When proof arrives after the deadline and the bank lists only the cutoff date, the desk checks the original transfer time.

Registration requires a full name, verified PGP ID, phone number and batch (2025-27 or 2026-28). Students can edit their name, phone and batch while a screenshot is being read. Unfinished details, the selected screenshot and payment-field corrections can be resumed in the same browser. The device clears the payment draft after a confirmed submission. Previously submitted proofs and issued tickets keep their status. The verified PGP ID stays tied to the account. Checkout shows the active recipients’ QR codes together. Students select the account they will pay. They can scan its code or tap **Open UPI app** on the same phone. They upload one JPEG, PNG or WebP screenshot up to 10 MB, check the extracted UTR, amount and time in IST, and explicitly confirm who received the transfer. They also identify the payer and beneficiary and accept the E-Cell fair-play declaration. Someone may pay on a player’s behalf. The player submits from their own account. The private Journal preserves each proof revision, including the original OCR and the student’s corrections.

### Reconciliation at the club desk

1. In **Payments → Bank statements**, select the receiver, confirm the account and upload the bank’s CSV, Excel or unlocked PDF. A UTF-8 CSV with **Date**, **UTR**, **Credit** and **Debit** is the simplest format. **Amount** plus a **Type** of **Credit** or **Debit** also works. Keep UTRs as text to preserve leading zeros.
2. **Preview matches** shows exact credits, flagged claims and other statement rows. **Apply preview** records accepted credits together in the private Journal. A change to the evidence requires a fresh preview. Repeat uploads and overlapping exports cannot spend the same credit twice. If a student submits proof later, reopen the statement to preview the new match.
3. **Payments → Needs Review** shows the reason, original screenshot, OCR values and candidate bank rows. Open the original statement, select the credit and record a reason. Linking keeps the payment pending. Approval consumes the verified credit. Rejection gives the student a reason and lets them replace the screenshot. A later reversal affecting an authorized entry is flagged for the club.
4. Google Drive reads screenshots and converts Excel/PDF files in the club folder. An exact match requires the full unused UTR, the correct account and a positive credit for the server quote. Unreadable fields, corrected claims, conflicts and uncertain PDF layouts go to review. For an unstructured PDF, the admin can transcribe a visibly identified incoming credit from the original and record their decision. Temporary conversion files are trashed.

Authorization issues the same entry QR in the player’s account, confirmation email and phone pass. **Open phone pass** displays the ticket. **Save pass to phone** downloads it for offline presentation. The desk shows delivery failures and can resend an active pass. Each valid ticket receives one seat at its first gate scan.

At the desk, **Walk-in or paid retry** shows the fee for the selected purchase. A retry requires elimination and a seat in a later qualifier wave. Six waves share 216 playing attempts. New registrations close at 11 PM IST on 27 November 2026. A physical exit and wristband return are free and update the person’s headcount independently of the purchased attempt.

All active tables in a wave start together. The floor manager reviews the draw, records all chip stacks and resolves any tied lead before closing the stage. The highest stack at each table advances. The first two rounds last 30 minutes and the final lasts 60 minutes. Each starts with 10,000 chips per seated player.

## Event operations

On a phone, sign in to the staff desk, open **Gate → Scan entry QR**, then tap **Start camera**. Check the player’s college ID and aim at their QR. The scanner opens on the event site with admission access tied to the staff session. It reads camera frames locally. Staff can enter the printed code when a camera is unavailable.

A green check shows the player and their numbered seat. The server holds the script lock while it reads the ticket and commits the first-scan time, next available seat in the booked qualifier wave and venue entry in one Journal row. Each table has six numbered seats. Qualifier draws keep these assignments, including gaps when a player is outside. A repeat shows **Already used** with the original time and seat. An unpaid, unrecognized or closed unused pass shows **Invalid ticket**. Players see their seats on the open pass or signed-in account.

A connection failure keeps camera check-in unconfirmed. Staff retry the same ticket after reconnecting. Offline actions entered at the desk stay queued on that device until the server confirms them. The floor board refreshes every 15 seconds while visible and uses trainer aliases.

Keep the Google files restricted to the club. Share individual staff keys through the club’s existing private channel. After reconciliation and the club’s dispute window, close registration, revoke staff keys and remove the screenshot files, contact data, payment journal and local offline queue according to club policy. The private Journal records event decisions and payment references. Use an unshared club-owned folder.

## Testing

Edit the scripts, styles and shared sponsor section in `web/`. The optimized event and sponsor artwork lives in `docs/assets/`. Run `npm run build` to regenerate the public styles, scripts, sponsor sections and Apps Script package.

The homepage and event desk use the organizers’ Poké Poker Night wordmark and E-Cell crest. The chip icon comes from the spade in the supplied wordmark. Both interfaces share the yellow, blue and red palette in `web/base.css`. [IMT Ghaziabad E-Cell](https://www.youtube.com/channel/UCY31HTa4tP6vbMFoO5TAk6g)

Run `npm ci` and `npx playwright install chromium` once. Use `npm test` for the server regression suite and `npm run test:e2e` for browser journeys. The browser suite runs the real event code against isolated student records, simulated Google storage and a test mailbox. It covers email recovery, duplicate submissions, QR readability at phone sizes, conflicting receiver choices, delayed OCR, payment review, entry QR, offline gate sync, desk retries, waitlist offers, table scoring and the public floor. A delayed-price test checks that the sign-in field stays in place and navigation reuses the server quote. To use installed Chrome, set the environment variable `POKER_BROWSER_CHANNEL` to `chrome`.

The capacity tests in `npm test` take 50 isolated clients through sign-in, payment upload, bank matching and gate admission with a simulated limit of 30 simultaneous executions. They also check overlapping gate writes, repeat scans, evicted uploads and a gate scan during pass email delivery. To measure the published service, `npm run test:capacity:live` makes one burst of 50 public pricing and floor reads and reports completion, retries and latency. Google currently allows 30 simultaneous executions per account. The event runs under the club account, so excess requests may need another attempt. [Apps Script quotas](https://developers.google.com/apps-script/guides/services/quotas)

After publishing Pages and Apps Script, run `npm run test:deploy`. This read-only smoke test checks the live routes, mobile layout, backend availability and public access boundaries. Live email delivery requires an explicitly requested send to the intended mailbox.
